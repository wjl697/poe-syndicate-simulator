# 辛迪加 —— 完整机制详解

本文档详尽说明《辛迪加》的全局机制与所有特殊情况，用于向他人完整介绍玩法。数据来源：`scripts/autoloads/game_manager.gd`、`scripts/gameplay/action_logic.gd`。

---

## 一、组织与成员

### 1.1 四大部门
| 部门 | 定位 |
|------|------|
| 运输部 | 物资与人员调配 |
| 防卫部 | 组织武力保障 |
| 科研部 | 情报与技术研究 |
| 调停部 | 内部纷争仲裁 |

### 1.2 部门构成与成员总池
- 每个部门 = **1 名首领 + 最多 4 名下属**（共 5 人上限）。
- 另有无部门的**自由人**，以及审讯室中的**在押人员**。
- 每局 **14 人**上场，其余 3 人在**替补席**（`bench_pool`）。
- **格拉维奇特殊禁场规则**：开局从 17 人池抽取 14 人上场时，**“格拉维奇”会被强制从初始上场池排除，固定置于替补席**。只有当场上有人被“逐出/退出组织”除名后，才可能作为替补抽上场。
- **初始部门分布预算**：开局除了 4 名首领与 4 名基础下属外，系统会随机分配 `extra_budget`（3 或 4）：
  - 随机到 4：每部门分配 2 名下属，剩余 **2 名自由人**。
  - 随机到 3：3 个部门有 2 名下属，1 个部门只有 1 名下属，剩余 **3 名自由人**。

### 1.3 星级（0~3 星）
- 0 星 = 无级游荡者（通常是自由人）。
- 星级影响：情报产出、处决/商谈效果、首领参战判定、提拔优先级。

### 1.4 关系（三种）
- **信任**（绿线）、**敌对**（红线）、**中立**（无线）。
- 影响：增援选择、操作可用性、背叛/商谈目标、首领参战判定。

## 二、回合与遭遇生成

### 2.1 每回合部门选择
每回合最多 **3 场**部门遭遇，固定结构：
- **运输部 / 防卫部 二选一**（随机）
- **科研部**（必出）
- **调停部**（必出）

**前提条件**（每部门独立判断）：
1. 该部门存在"在场且未在押"的成员
2. 该部门情报未满 100%（安全屋未就绪，就绪则跳过本部门遭遇）

### 2.2 遭遇生成流程
- 本回合部门顺序 `shuffle()` 打乱。
- **成员按需生成**：只在玩家实际遇到该场遭遇时才生成成员（避免多场遭遇竞争占用成员）。
- 每场遭遇 = **1 名主成员 + 至多 3 名增援**（上限 4 人）。

### 2.3 主成员选择
1. **优先**：本部门活跃下属（非首领、在场、未在押、未锁定）随机选 1。
2. 无活跃下属 → 用**在押下属**（遭遇开启的第一时间由系统自动提前释放并结算情报，随后参与遭遇）。
3. 该部门下属全部在押且均被锁定（无法参与）→ 首领不单独出场，整场跳过。

> **注意**：部门"首领+至少1下属"是底层规则。每回合生成遭遇前及遭遇间推进时均会执行**自动补员**（确保每个部门至少有一名下属）。

### 2.4 全局遭遇锁定
代码中存在一段"遭遇锁定"检查（`_generate_single_encounter` 开头）：若当前遭遇仍有未处理成员，则本次生成退化为单人遭遇。
> **实际说明**：此检查为**防御性代码**。实际流程中，`generate_encounter`（新回合）和 `advance_encounter_queue`（推进下一场）都会**先清空当前遭遇**再生成新遭遇，因此该锁定检查永远不会触发。

### 2.5 首领参战合规判定（`leader_eligible`）
首领需同时满足：
1. 部门存在首领
2. 首领未在押、在场、未被锁定

且满足以下**任一**：
- 主成员与首领**有关系线**（信任/敌对）
- 部门下属**总星级 ≥ 3**（含在押下属、未揭示下属默认按 1 星）

首领合规后，通过「首领 VIP 通道」判定实际参战：基础概率 **5%**（可被天赋提升至 **10%**）。

### 2.6 增援槽位（"微信拉群邀请模型"）
- 最多 3 个槽位，`enc_members >= 4` 时停止。
- 基础激活率依次 `[35%, 25%, 15%]`。
- **全局增援修正**：基础乘数 **1.65**（天赋 15% + 圣甲虫 50%）。
- **关系链修正**：候选池中与主成员有关系 → `max_rel_factor` 取 3.0（敌对）/ 2.0（信任）。
- 最终概率公式：`final_rate = base_rate * 1.65 * max_rel_factor`。
- 任一槽位激活失败 → **Early Stop** 终止后续槽位生成。

### 2.7 候选池过滤与权重

**排除条件**：主成员本人、已锁定成员、已入队成员、不在场、在押。

**特殊过滤**：
- 安全屋就绪（100%情报）的其他部门成员不支援。
- 本部门首领：不合规或已通过 VIP 通道加入 → 排除。
- **跨部门中立者**：跨部门且与主成员无关系 → 排除。
- **自由人容量门槛**：部门满员（5人）**不允许自由人参战支援**；自由人支援数 ≤ 部门剩余空位。

**完整权重表**：
| 候选人情形 | 基础权重 | 最终权重（算入VIP/天赋倍率） |
|---|---|---|
| 本部门首领 + 有关系 (VIP) | 30.0 × 2.0 | **60.0** |
| 跨部门/同部门下属 + 有关系 (VIP) | 30.0 | **30.0** |
| 本部门首领 + 无关系 | 12.0 | **12.0** |
| 本部门同僚下属 + 无关系 | 4.0 | **4.0** |
| 自由人 + 无关系 | 1.0 | **1.0** |

### 2.8 遭遇验证（`_validate_encounter`）
1. **部门级屏蔽**：遭遇部门情报已满 100% → 整场跳过
2. **成员级过滤**：排除已入狱（本部门在押下属除外）、不在场、所属部门安全屋已就绪者
3. **锚点检查**：无本部门存活成员作主干 → 整场跳过
4. **增援关系校验**：同部门部下无条件保留；自由人无条件保留；跨部门成员必须与主干有关系线

## 三、遭遇操作

### 3.1 操作可用性
| 剩余未处理成员 | 可用操作 |
|--------------|---------|
| ≥ 3 | 审讯 + 处决 + 释放 |
| 2 | 审讯 + 释放 +（信任→背叛 / 上下级→首领出处决、下属出背叛 / 其他→处决） |
| 1 | 审讯 + 商谈 + 释放 |

> 释放始终可用（中间按钮）。
> **注意**：所有被操作的成员必须是当前遭遇在场人员。在押人员不能参战也不能被直接点击操作。

### 3.2 审讯（Interrogate）
- **触发**：始终可用（已被囚禁者不可选）
- **囚禁 3 回合**，每回合为**遭遇部门**产出情报：
  - 首领：`星级 × 3`
  - 下属：`星级 × 2`
  - 自由人：固定 `1`
- **最多同时 3 人在押**；审讯第 4 人时触发**强行挤出**，最早入押者强制释放（扣 1 星，不发放剩余未领情报）。
- **首领审讯**：立即卸任，新首领按三级顺序产生（见 8.1）。
- **释放时降 1 星**；降至 0 星变为自由人。

### 3.3 处决（Execute）
- **触发**：剩余 ≥3 人，或特定关系下 2 人时。
- **效果**：星级 +1（上限 3）。
- **自由人处决**：0 星自由人在遭遇中被处决后，**等级升为 1 星并直接加入该遭遇战部门**（若部门已满 5 人，自由人在生成阶段即无法参战）。
- 星级已满 3 → 无升星效果。

### 3.4 释放（Release）
- 始终可用。
- **效果**：释放目标，不会获得情报，组织无任何变化。

### 3.5 背叛（Betray）
- **触发**：仅剩 2 人时，且双方信任关系或上下级非首领时。
- 7 种效果详见第四节。

### 3.6 商谈（Bargain）
- **触发**：仅剩 1 人时。
- 13 种效果详见第五节。

## 四、背叛效果（7 种）

| 效果 | 生效条件 | 效果 |
|------|---------|------|
| 窃取情报 | 有目标 | 本部门 +6 情报；与目标变敌对 |
| 窃取阶级 | 有目标 | 执行者星级 +目标星级（上限3）；目标星级清零、变自由人（若目标原为首领则卸任并触发新首领提拔）；双方变敌对 |
| 逐出组织 | 有目标 | 目标被逐出组织，触发替补补位与状态清空（见 8.3） |
| 打压宿敌 | 双方不同部门 | 本部门全体 +1 星；目标部门全体 -1 星（成员降至 0 星脱离部门变自由人；首领降级则卸任并触发新首领提拔）；双方变敌对 |
| 摧毁敌对部门装备 | 双方不同部门 | 目标部门全体装备清零；双方变敌对 |
| 获取对方部门情报 | 双方不同部门 | 目标部门 +20 情报；移除双方关系（变中立，不设敌对） |
| 篡位 | 上下级、执行者非首领 | 执行者成为本部门新首领；目标失去首领；双方变敌对 |

## 五、商谈效果（13 种）

| 效果 | 生效条件 | 效果 |
|------|---------|------|
| 获取情报 | 始终可用 | 遭遇部门情报：3星=8、2星=6、1星/0星=4 |
| 获取大量情报 | 始终可用 | 遭遇部门情报 +20 |
| 结盟 | 盘上有已揭示非信任成员 | 按目标类型细分处理（见下） |
| 退出组织 | 始终可用 | 执行者自己被逐出组织，触发替补补位与状态清空 |
| 化解部门恩怨 | 本部门有敌对关系 | 移除本部门全体成员的所有敌对关系 |
| 摧毁部门装备 | 始终可用 | 本部门全体装备清零 |
| 调动职位 | 存在同星级同职务他部门成员 | 目标需已揭示且未在押，双方互换部门 |
| 劫狱 | 审讯室有在押囚犯 | 释放全部囚犯（正常降1星）；按剩余刑期一次性结算发放情报 |
| 获取传奇/通货/隐匿/地图/甲虫 | 始终可用 | 获得对应道具 |

### 结盟（FORM_TRUST_ANY_GAIN_INTEL）细分
| 目标类型 | 效果 |
|---------|------|
| 非敌对自由人 | 目标升星(0→1) + 加入遭遇部门 + 变信任（无 +4 情报） |
| 敌对成员（非自由人） | 关系变中立 + 目标部门情报 +4 |
| 中立成员（跨部门/同部门） | 关系变信任 + 目标部门情报 +4 |

> **特别标注**：已揭示的「敌对自由人」被系统显式排除在结盟候选池外，不会被选为结盟目标。

## 六、情报与藏身处

### 6.1 情报获取途径
- **审讯在押成员**：首领星级×3、下属星级×2、自由人1（每回合，归属遭遇部门）
- **背叛**：窃取情报+6、获取对方部门情报+20
- **商谈**：获取情报（按星级 4/6/8）、获取大量情报+20、结盟+4
- **劫狱**：释放囚犯时获得"剩余回合 × 每回合情报"一次性结算

### 6.2 情报满值处理
- 情报达 100% → 安全屋就绪（`safehouse_ready`）。
- **本部门在押成员立即释放**（星级 > 1 减 1，1 星保持不减，保护下属不脱离部门）。

### 6.3 情报衰减
- 满情报后 **3 次遭遇战未突袭** → 强行掉落衰减至 **90%**。

### 6.4 突袭藏身处
- 条件：情报满 100%
- 效果：
  1. 本部门在押成员全部释放（rank > 1 减 1，1 星保持不减）
  2. 原首领变为 **0 星自由人**
  3. 新首领晋升（最高等级下属 → 自由人 → 他部门调任）
  4. 部门情报重置为 0

## 七、审讯与监狱细节

### 7.1 每回合情报产出与归属判定
- 每场新遭遇开启时处理所有在押成员。
- 情报归属部门按 3 级 Fallback 解析：`prison_intel_division`（遭遇部门） → 自身部门 → 当前遭遇部门。
- 刑期 -1，归零释放。

### 7.2 提前释放（遭遇参战）
- 在押下属参与本部门遭遇时，遭遇开启第一时间即由系统自动提前释放。
- **一次性发放"剩余回合 × 每回合情报"**。
- 扣星（rank > 1 减 1，1 星保持），释放后留在原部门参战。

### 7.3 三种释放路径的降星差异
| 路径 | 降星规则 |
|------|---------|
| 情报满释放 / 突袭释放 / 提前释放 | rank > 1 减 1，1 星保持不减（保护下属不变成自由人） |
| 到期释放 / 强挤释放 / 自动补员强拉 | rank > 0 减 1，降至 0 星非首领变自由人 |
| 突袭的原首领 | 直接重置为 0 星自由人 |

## 八、首领提拔与部门补员

### 8.1 首领提拔三级顺序
1. **部门内最高等级下属** → 提拔（同分随机）
2. 无下属 → **从自由人随机提拔**（星级保底 ≥ 1）
3. 无自由人 → **从其他部门调任普通成员**（原部门星级作废，重置为 1 星；**首领不可调任**）
4. 全无 → 首领空缺

### 8.2 自动补员
- **触发时机**：新回合生成时及**遭遇战推进间隙（`advance_encounter_queue`）**。
- 部门仅剩首领（无下属）时自动补员：
  1. 优先从自由人随机补 1 名下属（星级保底 ≥ 1 星）。
  2. 无自由人 → 强制释放本部门一名在押成员补充（扣 1 星，保底 1 星）。

### 8.3 逐出/退出组织的替补补位与清理链
- 成员被除名（背叛逐出 / 商谈退出）后：
  1. **状态彻底清空**：被除名者的**所有已有关系线（信任/敌对）被全部删去**；若原本是首领则卸任并触发新首领提拔。
  2. **归入替补席**：重置为"0星自由人、未翻牌"进入 `bench_pool`。
  3. **替补补位**：从 `bench_pool` 随机抽 1 名新成员上场，初始为**未揭示（暗卡 `is_revealed=false`）、0 星自由人**。

## 九、装备系统

- 成员装备数（`equipment_count`）上限 3。
- 当前仅有**摧毁装备**效果（背叛/商谈），**无获取装备机制**。
- 处决不会获得装备（官方 Wiki 描述的"处决获得装备"未实现）。

## 十、运行模式

| 模式 | 说明 |
|------|------|
| 经典模式 | 标准流程，系统随机预掷背叛/商谈效果 |
| 沙盒模式 | 自由布阵，可自由选择背叛/商谈效果（支持效果可用性校验） |
| 教学模式 | 关卡式引导教学，支持指定人物与头像覆写展示 |
| 画板模式 | 电子画板教学推演 |

---

## 十一、预掷机制（经典模式）

- 遭遇剩 2 人 → 为双方**预掷背叛效果**。
- 遭遇剩 1 人 → 为剩余者**预掷商谈效果**（含预选目标）。
- 效果未预掷（-1）时，显示效果池中第一个有效效果说明。

---

## 十二、系统机制（撤销与存档）

### 12.1 撤销系统 (Undo System)
- 系统自动维护最多 **10 步历史状态栈**（`history_stack`）。
- 玩家的每次决策操作、遭遇推进、藏身处突袭或沙盒调整均可进行历史回滚。

### 12.2 磁盘持久化存档 (Save & Load)
- 三种模式各自独立存储进度：
  - 经典模式：`user://save_classic.json`
  - 沙盒模式：`user://save_sandbox.json`
  - 教学模式：`user://save_tutorial.json`
