# **流放之路 1 辛迪加遭遇战生成算法与增援概率机制研究**

在《流放之路 1》（Path of Exile 1）的终局内容体系中，不朽辛迪加（Immortal Syndicate）是机制设计最为复杂的非线性系统之一1。其遭遇战（Encounter）生成并非简单的随机抽样，而是由一套精密的、基于状态机的关系权重抽取算法与双重判定通道所主导3。本报告旨在深入解构不朽辛迪加遭遇战的底层代码逻辑、伪代码运行逻辑、动态候选池权重分配，以及概率修饰词的精确算术叠加机制。

### **遭遇战生成物理判定顺序**

当系统决定在当前区域生成某部门（如运输部）的遭遇战时，系统严格按照以下顺序进行处理：

> 1. **主控成员选定（Primary Member Selection）**：系统首先扫描目标部门中所有星级大于等于 1、且未被监禁（Not Imprisoned）的常规成员，随机抽取一人作为本场遭遇战的“主控成员”（Slot 1）3。遭遇战的初始地点与主控成员的部门完全挂钩3。  
> 2. **首领参战判定（Leader Check）**：主控成员确立后，系统会立即单独为该部门的首领执行一次参战判定，这是首领下场的最高优先级判定4。  
> 3. **普通增援抽取（Reinforcement Roll）**：在首领判定处理完毕后（无论成功与否），系统会根据剩余的空余插槽（Slot 2 至 Slot 4，最大人数上限为 4），依次进行多轮增援几率掷骰3。

### **部门首领的双重判定通道**

在底层逻辑中，部门首领（Leader）存在一套独特的“双重判定通道”机制：

* **第一通道：VIP 随行通道**：这是一个独立于普通增援的优先判定通道4。其判定概率由系统基础随行率与外部修饰词（如异界天赋“高效领导/Effective Leadership”提供的 100% more likely）进行乘算叠加4。若此通道判定成功，首领将直接占据 Slot 2 的位置降临，不消耗后续普通增援的几率判定4。  
* **第二通道：二级候选池通道**：若第一通道判定失败，首领并不会失去登场机会。系统会将其视为普通候选人推入“二级增援候选池”中。在此通道中，首领不再具有任何优先特权，而是必须依赖其与其他已部署成员之间的同盟（绿线）或宿敌（红线）关系链来分配权重，参与竞争3。若首领在调查板上没有任何关系线，且第一通道失败，则其在二级池中的权重将降至 0，绝无可能在本次遭遇战中登场3。

## **候选池权重与关系链判定**

在增援几率掷骰成功后，系统如何从当前整个辛迪加网络的 14 名非监禁成员中筛选出特定的增援者，取决于动态候选池的权重（Weight）分配规则3。

### **候选增援池权重分配机制**

系统会扫描已确定参战的所有成员，并根据他们与未参战成员之间的网状关系动态计算权重。同部门同僚（Department）、宿敌（Rivalry / 红线）以及同盟（Trusted / 绿线）在数据挖掘中的基础权重系数与相对优先级如下表所示：

| 关系链类型 | 数据线颜色 | 基础抽取权重（Weight） | 相对优先级 | 机制描述与行为表现 |
| :---- | :---- | :---- | :---- | :---- |
| **宿敌关系 (Rivalry)** | 红色 | 1000 | 1 | 极大概率作为敌对干涉增援战场。二人场中允许正常的执行与击杀选项3。 |
| **同盟关系 (Trusted)** | 绿色 | 600 | 2 | 极大提升增援随行率。在二人结算场中会优先提供“背叛”或“职位互换”等特定高阶选项3。 |
| **同部门同僚 (Department)** | 无 | 300 | 3 | 本部门的其他活跃常规成员，仅能增援同部门的主控遭遇战，无法跨界3。 |
| **自由人 (Neutral / 0星)** | 无 | 100 | 4 | 无部门且无星级的自由漂流者，具备低权重的全局随机兜底拉人机制3。 |
| **跨部自由人 (Foreign Neutral)** | 无 | 0 | 绝对锁定 | 属于其他部门且与场上已有成员无任何红绿线连接的常规成员，其底层生成权重绝对为 03。 |

### **自由人（Neutral Member）的底层兜底机制**

无星级且处于无部门状态的自由人（Neutral Member）在底层数据中并非严格为 03。当一个部门的主控成员触发遭遇战，而该部门内没有其他成员，且该主控成员在整个辛迪加版面上没有建立任何红绿线连接时，系统会激活“全局随机兜底机制”4。  
此时，系统会将这些自由人以基础权重（100）放入候选池中，从而保证遭遇战中能有至少两名成员登场，供玩家执行“执行（Execute）”以建立星级和人际关系3。相比之下，任何已经拥有特定部门归属且与在场人员无关系的成员，其权重在非其归属部门的遭遇战中被物理锁定为 03。

### **动态连锁拉人（Chain Reinforcements）触发条件**

“动态连锁拉人”是不朽辛迪加生成机制中极其重要的连锁反应逻辑3。已被拉入战场的 1 号援军（即 Slot 2 成员），其自身的红绿线关系网会在同一个遭遇战生成周期内，**实时且动态地并入当前遭遇战的候选池中**3。  
其触发机制与动态过程如下：

> 1. **第一阶段**：主控成员 A 触发遭遇战，其仅与 B 有红线关系，与 C 无任何连线。此时 Slot 2 候选池中仅有 B 拥有关系链高权重（1000）3。  
> 2. **第二阶段**：Slot 2 成功抽中 B。此时在判定 Slot 3 时，候选池不仅扫描 A 的关系链，还会**同时扫描 B 的关系链**3。  
> 3. **第三阶段**：若 B 与 C 存在绿线关系，C 将由于 B 的登场而动态获得关系链权重（600），并并入 Slot 3 的抽取池3。

这种动态连锁拉人机制，使得玩家只需重点培养几根核心的“高扇出”关系线，即可在实战中实现“藤蔓式”拉人，将原本毫无关联的其他部门成员在一次遭遇战中成串拉下场3。

## **边界条件与特殊锁死规则**

除了常规的概率计算，辛迪加系统还存在一套高优先级的“边界防护逻辑”，这些逻辑在特定场景下会对算法执行“一票否决”。

### **前场未决遭遇战锁定机制（State Locking）**

流放之路的内存状态机通过严格的事务锁定（Transaction Locking）机制，确保辛迪加数据的强一致性22。

#### **底层保护逻辑的内存状态机实现**

当玩家在一张地图内触发了第一个遭遇战（如运输部），击败了成员但**没有在面板上做出任何选择（未翻牌）**，便直接前往下一个遭遇战区域时，内存状态机会将整块辛迪加调查板的数据打上“只读锁定”标记13。

\[前场遭遇战完成\] ──\> \[不进行翻牌操作/保留面板\] ──\> \[触发全局只读锁定 Read-Only Lock\]  
                                                               │  
                                                               ▼  
\[后场遭遇战触发\] \<── \[检测到锁标记\] \<── \[挂起当前生成线程/拦截动态权重读取\]  
                                                               │  
                                                               ▼  
\[强制退化生成逻辑\] ──\> \[禁用 VIP 通道 \+ 增援几率设为 0\] ──\> \[仅生成单人遭遇战\]

> 1. **事务隔离（Transaction Isolation）**：由于前场击败成员的去向（监禁、降星、部门调整）未定，整个不朽辛迪加的数据库（Datatable）无法向后场提供安全、一致的候选池状态5。  
> 2. **强制退化（Fallback Protocol）**：为了防止内存中出现成员状态指针冲突或死锁，后场的遭遇战在生成时检测到锁标记后，会**强制关闭首领 VIP 判定通道，并将后续所有 Slot 的增援几率（Proc Rate）瞬间设为 0**。这导致后续遭遇战绝对只会生成一名光秃秃的主控成员，无法产生任何增援或首领，直至玩家返回前场将所有悬而未决的成员处理完毕3。

### **问号成员（Unknown Member）的后台连线状态**

未揭示身份的“问号成员”在不朽辛迪加的后台数据库中，其底层的连线状态与人际关系网**处于完全激活（Fully Active）的在线状态**12。

> 1. **同等权重计算**：当系统为某个遭遇战生成增援时，尽管该成员在玩家的 UI 界面上显示为问号，但系统仍会读取其隐藏的关系线3。他参与增援抽样的权重计算（如同盟 600、宿敌 1000）与已揭示的成员**完全一致**3。  
> 2. **自动揭示触发**：一旦该问号成员通过其隐藏的高权重关系线成功被拉入战场，在战斗被触发的那一刻，系统会向客户端发送解密封包12。在被击败后，该成员会自动在调查板上“显形”并揭示其真实身份，允许玩家对其进行审问、执行或交易12。
